
最合理的方案是把实验分成三个独立场景：

1. 城市客户端数均衡：研究跨城市异质性和个性化；


2. 城市客户端数自然不均衡：研究城市权重 \(\alpha\)；


3. 留一城市：研究冷启动和跨城市迁移。



现阶段主方法应暂定为“城市平衡分层 FedAvg”。FedProx、FedBN、LocalHead 是否保留，必须等修复后的消融结果决定，不能预设它们一定有效。

以下判断基于你最新的实验结果与问题总结。

一、当前结果应该怎样解读

目前可以得出的结论：

在“每城固定10站点”的均衡场景中，FedAvg 是当前最好方法；

FedProx 比 FedAvg 差；

FedBN+LocalHead 比普通 FedProx 差；

当前集中式模型存在明显的归一化、模型表达或评估问题；

当前 \(\alpha\) 实验没有验证价值。


目前不能得出的结论：

不能说 \(\alpha\) 没用，因为当前每个城市的 \(N_c\) 完全相等，\(\alpha\) 数学上就是空操作；

不能直接说“六城市异质性不存在”，因为 FedBN-only 和 LocalHead-only 结果完全相同，很可能还有开关、结果映射或本地参数保存问题；

不能把 centralized 称为理论上限，因为当前 centralized 只是“一个共享模型＋全局归一化”，并不是足够强的集中式个性化模型；

不能把多城市 Macro-RMSE 19.93 与深圳单城市 RMSE 63.00直接比较，两者城市范围和负荷尺度完全不同；

Seasonal Naive 是确定性算法，本来就没有随机种子方差，其 std=0 是正常的；只有 Local-only 的 std=0 需要修复后重跑。


二、重新设计三个数据场景

场景A：城市均衡，用于研究异质性

每个城市选择相同数量的站点，例如每城10个，共60个客户端。

但不要再选负荷最大的 Top-10，建议按以下维度分层抽样：

低、中、高负荷；

低、中、高零值率；

不同充电桩数量；

不同站点类型。


这个场景下，每个城市的数据量近似相等，因此：

不需要比较 \(\alpha=0/0.5/1\)；

固定城市等权即可；

主要比较 FedAvg、FedProx、FedBN、LocalHead；

回答“即使城市规模相同，跨城市分布差异是否仍然存在”。


你现有的每城 Top-10 实验可以视为这个场景的早期版本，但因为 Top-K 有大型站点偏差，正式论文建议改成分层抽样后重跑。

场景B：自然不均衡，用于研究城市平衡

固定总客户端预算60，但按照有效站点数量分配，并保证每城至少2个站点。

比附件中总数为63的示例更合理的一个60客户端分配是：

城市	有效站点	建议客户端数

AMS	986	26
SZH	752	21
LOA	139	5
JHB	22	3
MEL	22	3
SPO	17	2
合计	1938	60


分配逻辑是：

1. 每个城市先保底2个，共12个；


2. 剩余48个按各城市超出保底部分的有效站点数分配；


3. 使用最大余数原则保证总数严格等于60。



注意，城市有效规模应该使用：

\[
N_c=\sum_{i\in c}n_i^{train}
\]

即该城市选中站点的有效训练窗口总数，而不是直接使用原始4392行，更不能使用测试期数据。

如果各站点训练窗口确实相等，上表对应的城市权重大约为：

城市	\(\alpha=0\)	\(\alpha=0.5\)	\(\alpha=1\)

AMS	0.167	0.304	0.433
SZH	0.167	0.273	0.350
LOA	0.167	0.133	0.083
JHB	0.167	0.103	0.050
MEL	0.167	0.103	0.050
SPO	0.167	0.084	0.033


这样 \(\alpha\) 才真正控制大城市与小城市之间的平衡。

所有 \(\alpha\) 实验必须使用完全相同的60个站点、时间切分和随机种子，只能改变 \(\alpha\)。

场景C：留一城市冷启动

每次留下一个城市，不让它参加联邦训练：

其他五城训练全局模型；

在被留出城市上直接测试，得到 zero-shot；

再允许使用7/14/30天目标城市数据微调，得到 few-shot；

与“使用同样少量数据从头训练”比较。


六个城市轮流留出，共六折。

这部分不需要依赖 \(\alpha\) 一定有效，能够单独形成论文的跨城市泛化贡献。

三、\(\alpha\) 实验如何正确验收

不能只用“重跑后RMSE不再相同”作为通过标准，因为不同权重也可能偶然得到相近指标。

应验证三层证据：

第一层：输入数据确实不均衡

每次运行保存并报告：

每城选中站点数；

每城有效训练窗口数 \(N_c\)；

每城占总训练数据比例。


第二层：聚合权重确实不同

在训练开始前打印或保存六个城市的 \(\beta_c\)。

必须确认：

\(\alpha=0\) 六城等权；

\(\alpha=0.5\) 为折中；

\(\alpha=1\) 接近自然数据比例。


第三层：聚合模型确实不同

在完全相同的客户端本地更新下，比较第一轮聚合后模型：

\(\alpha=0\) 与0.5的全局模型不能完全相同；

\(\alpha=0.5\) 与1也不能完全相同。


只有这三层都通过，才开始跑50轮正式实验。

论文最终应观察：

Macro-City WAPE；

最差城市WAPE；

六城市分别指标；

大城市和小城市之间的性能差距；

Micro指标作为补充。


如果 \(\alpha=0.5\) 没有最好，就不要强行保留“0.5最优”结论，应根据验证集选择真实最佳值。

四、先排查 FedBN 和 LocalHead，不要直接重跑

fedbn_only 与 localhead_only 三项指标完全相同，这是高度异常现象。两种结构不同，正常情况下不应得到完全相同模型。

需要先完成以下机制验收。

FedBN验收

训练后检查：

不同客户端的 BN running mean/variance 是否不同；

BN参数是否没有被服务器聚合；

下一轮全局模型广播时，本地BN是否没有被覆盖；

测试时是否加载了对应站点自己的BN，而不是最后一个客户端或全局BN。


LocalHead验收

检查：

不同站点的预测头参数是否真的不同；

本地预测头是否没有上传服务器；

下一轮广播时本地头是否保留；

最终测试是否使用该站点自己的预测头；

保存最佳模型时是否同时保存了所有本地头。


结果整理验收

还要确认：

fedbn_only 与 localhead_only 的配置文件确实不同；

结果整理脚本没有把两个实验映射到同一个目录；

两者实际运行轮数、方法标记和checkpoint不同。


机制验收通过后，再做完整的 \(2\times2\) 消融：

实验	FedBN	LocalHead

Base	否	否
FedBN-only	是	否
LocalHead-only	否	是
Both	是	是


所有组使用相同数据、50轮、相同3个种子。

判断方法：

FedBN贡献：FedBN-only 对比 Base；Both 对比 LocalHead-only；

LocalHead贡献：LocalHead-only 对比 Base；Both 对比 FedBN-only；

组合贡献：Both 对比两个单模块。


如果机制确认无误后 Both 仍然最差，就应从主方法中删除 FedBN/LocalHead，不能因为它们听起来先进就强行保留。

五、FedProx为什么可能更差，怎么处理

当前 FedProx 22.07，FedAvg 19.93，说明当前 \(\mu\) 或本地训练强度可能不合适。

FedProx并不保证必然优于FedAvg。当：

数据异质性不强；

本地epoch较少；

\(\mu\) 太大；

模型本身欠拟合；


近端约束会限制客户端学习，反而降低性能。

建议先做小规模验证集搜索：

\(\mu=0\)：等价于FedAvg；

一个较弱约束；

当前0.01；

一个较强约束。


同时只测试本地epoch 1、3、5。不要一次搜索大量组合。

如果多个种子、两个数据场景下 FedProx 都不如 FedAvg，就应使用 FedAvg 作为论文主聚合器，把 FedProx放在基线中。

六、集中式模型必须重新定义

当前 centralized 垫底，最大嫌疑不是“集中学习天然不行”，而是以下问题：

1. 将高负荷站点和低负荷站点用同一个目标Scaler；


2. 测试反归一化时Scaler对应错误；


3. 模型不知道输入来自哪个城市、哪个站点；


4. 一个共享预测头无法同时处理不同站点尺度；


5. centralized与Local-only的训练预算、早停标准不一致。



推荐的集中式基线应当：

每个站点分别用训练期统计量标准化；

汇总标准化后的滑动窗口训练；

模型输入加入城市、站点或静态属性；

测试时使用对应站点Scaler反归一化；

可以设置共享主干＋站点预测头；

与联邦模型使用相同主干、损失和时间切分。


最好保留两个集中式结果：

名称	含义

Centralized-shared	一个完全共享模型
Centralized-personalized	集中数据＋共享主干＋站点头


只有后者更适合作为性能参考上限。前者如果仍然较差，应称为“集中式共享模型”，不要称“理论上限”。

七、评价指标也要调整

当前不同城市负荷尺度差异很大，论文不宜把原始 Macro-RMSE作为唯一主指标。

建议：

主指标：Macro-City WAPE；

辅助指标：Macro-City MAE、NRMSE；

公平性指标：Worst-City WAPE；

分城市结果：六城市分别报告；

Micro-WAPE：作为反映自然数据分布的补充；

冷启动：报告相对从头训练的提升比例。


多城市 Macro-RMSE 不能直接和深圳单城市 RMSE比较。正确比较方式是：对于每个城市，比较该城市在单城FL和多城FL下的相同指标，然后再对六个城市的改善率取平均。

八、Clustered实验怎么处理

Clustered当前不是核心优先级，建议暂时停止。

如果论文核心已经包含：

城市数据不平衡；

分层聚合；

个性化；

冷启动；


再加入模型参数谱聚类会使论文线索过多，而且当前还OOM。

如果后续确实需要聚类，优先考虑：

根据训练期平均日曲线、24h/168h自相关和负荷规模对城市聚类；

只聚类6个城市，而不是聚类所有站点模型；

使用CPU计算；

不保存所有客户端完整GPU参数。


如果不产生明确提升，可以直接删除Clustered实验，不影响论文主体。

九、推荐的执行顺序

第一阶段：只验证机制，不跑正式实验

1. 修复 Local-only 随机种子；


2. 确认 Seasonal Naive 无需多种子；


3. 验证 FedBN、LocalHead开关真实生效；


4. 修复集中式归一化和反归一化；


5. 建立场景A和场景B固定站点清单；


6. 验证 \(N_c\)、\(\beta_c\) 和第一轮聚合模型。



任何一项没通过，都不要启动50轮实验。

第二阶段：快速筛选

使用10轮、1～2个种子：

1. 场景A：Base/FedBN/LocalHead/Both；


2. 场景B：FedAvg的 \(\alpha=0/0.5/1\)；


3. 小规模FedProx \(\mu\) 搜索；


4. 修复后的centralized smoke test。



这一阶段只使用验证集做决定。

第三阶段：正式论文实验

只把第二阶段有效的方法扩展到50轮、3个种子：

1. 场景B的 \(\alpha\) 主实验；


2. 场景A和B的个性化消融；


3. 六城市单城市FL；


4. Local-only、Centralized、Seasonal Naive基线；


5. 六折留一城市冷启动。



第四阶段：决定最终论文主线

按照真实结果选择：

若 \(\alpha=0.5\) 改善Macro和最差城市：主推城市平衡分层FL；

若FedBN/LocalHead只帮助小城市：作为条件个性化模块，不宣称普遍有效；

若FedBN/LocalHead整体无效：从完整方法删除；

若多城市显著帮助低资源城市：主推跨城市知识共享和冷启动；

若多城市普遍不如单城市：研究重点转为负迁移诊断，而不是强行宣称多城市更好。


最重要的一点是：

> 现有“每城10站”的结果不是全部作废，它可以保留为城市规模均衡的控制实验；真正需要新增的是一个自然不平衡场景。这样既能解释为什么原来的 \(\alpha\) 完全相同，也能让论文实验结构更加清楚。
